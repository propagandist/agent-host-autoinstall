\section{はじめに}
%======================================================================

\subsection{この手順書の目的}
社内のオンプレミスの PC を、AI コーディングエージェント(Claude Code、Codex ほか)を
Orca で並列に動かす「常時稼働のエージェントホスト」にするための手順をまとめる。
USB メモリ 1 本からほぼ無人でインストールでき、再起動や停電のあとも人手を介さずに、
RDP で接続できる状態に戻ることを目指す。

仕様は \code{docs/SPEC.md}、経緯と未確認の事項は \code{docs/HANDOVER.md} にある。
この手順書と食い違ったときは、リポジトリの文書とスクリプトを正とする。

\subsection{対象読者}
このリポジトリを使ってホストを用意する社内の管理者・作業者。
Linux の基本的な操作(端末、SSH、apt)ができることを前提とする。

\subsection{この手順書の読み方}
コマンドの枠の右上に、どこで打つかを書いている。
\begin{local}
just status <ホスト>     # 手元の PC(リポジトリの直下)で打つ
\end{local}
\begin{host}
sudo systemctl reboot    # just ssh などでホストに入り、sysadmin で打つ
\end{host}
\begin{term}
gh auth status           # RDP で入った agent のデスクトップの端末で打つ
\end{term}
\begin{hint}
\code{<ホスト>} はホスト名か IP アドレスに置き換える。囲みは、\textcolor{cautioncol}{\textbf{注意}}(誤ると戻せないこと)、
\textcolor{hintcol}{\textbf{ヒント}}(知っておくと楽なこと)、\textcolor{checkcol}{\textbf{確認}}(確かめること)の 3 種類。
\end{hint}

\subsection{できあがる環境}
\begin{itemize}
  \item OS: Ubuntu Desktop 26.04 LTS(GNOME 50、Wayland のみ)
  \item 遠隔操作: GNOME の「デスクトップ共有」(RDP、ポート 3389)。物理の画面のセッションをそのまま共有する
  \item 管理: SSH(\code{sysadmin} ユーザー、鍵認証のみ)
  \item エージェント: Orca(ADE)、Claude Code、Codex、選択で OpenCode・GitHub Copilot CLI・Antigravity CLI
  \item 開発環境: Node.js、Python(uv)、mise、rootless Docker、Google Chrome、エディター(選択)
  \item 通知: Slack と IP Messenger(承認待ち・エラー・完了)
\end{itemize}

\subsection{ユーザー}
\noindent{\small\begin{tabularx}{\linewidth}{@{}lllL@{}}
\toprule\headrow
ユーザー & 用途 & sudo & ログイン \\
\midrule

\code{agent} には個人の秘密情報を置かない。

\subsection{セキュリティ上の前提}
\begin{caution}
空パスワードのキーリングと自動ログインは、社内 LAN に限ったホストで、秘密情報を置かない専用ユーザー
\code{agent} が使うことを前提に許している。SSH(22)と RDP(3389)はインターネットに開けない。
社外からは VPN 経由とする。
\end{caution}

\section{準備するもの}
%======================================================================

\subsection{ハードウェア}
\begin{itemize}
  \item x86\_64 の PC。メモリ 32GB 以上、NVMe SSD を推奨。ディスクは全体を消して使う
  \item HDMI のダミープラグ。モニターなしでも描画させるため。
        RDP の解像度はプラグの解像度になる(手元からは変えられない)ので、\textbf{1920×1080 のもの}を選ぶ
  \item USB メモリ(8GB 以上)
  \item 有線 LAN。インストール中にネットワークが要る(Desktop の ISO には openssh-server が入っていない)
\end{itemize}

\subsection{作業用の PC}
手元の PC での作業は just\footnote{\url{https://just.systems/}}で行う。リポジトリの直下で \code{just} を実行すると、
レシピの一覧が出る。Linux の道具(xorriso、shellcheck、TeX など)が手元になければ、Docker の Ubuntu 26.04 の中で動く。
\begin{checklist}
  \item just
  \item Windows なら Git Bash(Git for Windows\footnote{\url{https://gitforwindows.org/}} に入っている。
        \code{C:/Program Files/Git/bin/bash.exe})と Docker Desktop\footnote{\url{https://www.docker.com/products/docker-desktop/}}。

  \item USB への書き込みに、Windows なら Rufus\footnote{\url{https://rufus.ie/}}(DD イメージのモード)
\end{checklist}

\section{インストール用の USB を作る}\label{sec:build}
%======================================================================

\subsection{ISO を作る}
\begin{local}
just check-env          # env.yaml を検査する
just fetch-iso          # Ubuntu の ISO を build/ に取得して SHA256 を照合する
just iso                # build/agent-host.iso を作る
\end{local}
\code{just fetch-iso} は、Ubuntu の公式のサイト\footnote{\url{https://releases.ubuntu.com/26.04/}}から
Desktop の ISO と SHA256 の一覧を取得する。

\subsection{just iso がすること}
\code{scripts/build-usb.sh} を呼ぶ。
\begin{enumerate}
  \item env.yaml を検査し、値を埋めた \code{autoinstall.yaml} と、スクリプト用の \code{env.sh}・公開鍵・CA 証明書を作る
  \item ISO の直下に \code{/autoinstall.yaml} と、スクリプト一式 \code{/agent-host/} を足す
  \item grub.cfg の起動行に \code{autoinstall} を足す(確認画面を出さないため)
  \item 元の ISO の起動の構成(BIOS と UEFI)を保ったまま書き出す
\end{enumerate}

\subsection{USB に書き込む}
\code{build/agent-host.iso} を、Rufus なら「DD イメージ」のモードで書き込む。Linux なら \code{dd} を使う。
env.yaml は安全な場所に保管しておく(入れなおしや移行で使う)。

\begin{caution}
できた ISO と USB には、パスワードのハッシュ、RDP のパスワード、Slack の Webhook の URL が入る。
使い終わったら消す。この USB から起動すると、\textbf{確認なしでディスク全体を消してインストールが始まる}。
対象以外の PC に挿したまま起動しない。
\end{caution}

%======================================================================
\section{BIOS の設定}
%======================================================================
\begin{checklist}
  \item 「Restore on AC Power Loss」(名称は機種による)を \textbf{Power On} にする
  \item UEFI で起動する。USB から起動できるようにする
  \item HDMI のダミープラグを挿す
\end{checklist}

%======================================================================
\section{インストール}
%======================================================================
\begin{enumerate}
  \item USB から起動する。確認画面は出ずにインストールが始まる
  \item インストーラーがディスク全体を LVM で使い、\code{sysadmin} を作り、openssh-server を入れる
  \item 最後に同梱のスクリプトを \code{/opt/agent-host} に置き、初回起動時の構成サービスを有効にして再起動する
  \item \textbf{再起動したら USB を抜く}
\end{enumerate}

VirtualBox(CPU 1、メモリ 4GB)ではインストールに約 50 分かかった。実機ではもっと速い。

\begin{hint}
インストール中、ライブ環境のログイン画面(「Live session user」)で止まって見えることがある。
インストールは裏で進んでいる。気になるなら \key{Enter} でログインすると進み具合が見える。
\end{hint}

Pro / Max / Team / Enterprise のアカウントでログインしているときだけ使える。通信は Anthropic のサービスを通る。
\begin{term}
claude remote-control   # 作業するディレクトリで。初回は確認に y
\end{term}
\begin{enumerate}
  \item 表示された URL か QR コードを、スマホの Claude アプリか claude.ai/code で開く
  \item プッシュ通知: Claude アプリに同じアカウントでログインし、端末の \code{/config} で「Push when actions required」などをオンにする
\end{enumerate}

\subsection{ファイルのやり取り}
\begin{itemize}
  \item SFTP: env.yaml に公開鍵を書いた人は、WinSCP\footnote{\url{https://winscp.net/}} などでホスト、ポート 22、ユーザー \code{agent}、秘密鍵で入る。作業の置き場所は \code{/home/agent/work}。シェルには入れない
  \item 小さなファイルは RDP のクリップボードでも渡せる(未検証)
\end{itemize}

\subsection{自動化が効かなかったときだけ}
\paragraph{ログインキーリング}
first-login の記録に \code{set-credentials} の失敗が出ていたら、キーリングが開いていない。
「パスワードと鍵」(seahorse)で「ログイン」キーリングのパスワードを空にし、
\code{/opt/agent-host/first-login/first-login.sh} を実行する。

\paragraph{デスクトップ共有}
設定 → システム → リモートデスクトップ →「デスクトップ共有」と「リモート操作」をオンにし、
認証情報を env.yaml の \code{rdp} の値にする。
\begin{caution}
「リモートログイン」は\textbf{オンにしない}(デスクトップ共有が 3390 番に移る)。
\end{caution}

\section{運用}
%======================================================================

\subsection{定期的な再起動}
unattended-upgrades はセキュリティ更新を自動で入れるが、作業中のエージェントを止めないよう自動では再起動しない。
カーネルなどの更新は再起動するまで反映されないので、\textbf{月 1 回、エージェントが作業していない時間に再起動する}。
\begin{local}
just ssh <ホスト>
\end{local}
\begin{host}
[ -f /var/run/reboot-required ] && cat /var/run/reboot-required.pkgs
sudo systemctl reboot
\end{host}
再起動後は何もしなくても RDP で接続できる状態に戻る。

\subsection{設定やバージョンを変える}
env.yaml を直したとき、スクリプトや固定するバージョン(スクリプトの先頭の版と SHA256)を直したときは、
OS を入れなおさずに反映できる。
\begin{local}
just update <ホスト>    # env.yaml から設定を作りなおし、スクリプトを入れ替えて、構成を再実行する
\end{local}
\begin{itemize}
  \item env.yaml のホスト名と、つないだホストの名前が違うと止まる(別のホストの設定を流さないため)
  \item 元の一式はホストの \code{/opt/agent-host.prev} に残る
  \item agent がログイン中だと、agent の環境変数の変更は次のログインで反映される
  \item Chrome は Google のリポジトリに最新版しかないため固定せず、unattended-upgrades が自動で上げる
\end{itemize}
\begin{caution}
ufw の許可は足すだけなので、\code{lan_cidrs} や \code{dev_ports} から外したものは手で消す
(\code{just ssh} → \code{sudo ufw status numbered} → \code{sudo ufw delete <番号>})。
\end{caution}

\subsection{環境を入れ替える(OS の入れなおし、機種の交換)}
ホストの身元(SSH のホスト鍵、RDP の証明書)、ログインと設定、\code{~/work} と Orca の worktree を移す。
ツールの本体、mise の言語、Docker のイメージ、Chrome のプロファイルは移さない(作りなおせる)。

\begin{figure}[htbp]
\centering
\begin{tikzpicture}[node distance=8mm and 20mm]
  \node[box,minimum width=28mm] (old) {古いホスト\\[-1pt]{\scriptsize 作業を止める}};
  \node[soft,right=of old,minimum width=34mm] (file) {書き出したファイル\\[-1pt]{\scriptsize 手元の PC ・ 暗号化して保管}};
  \node[box,right=of file,minimum width=28mm] (new) {新しいホスト\\[-1pt]{\scriptsize 同じ env.yaml で just iso}};
  \node[box,below=of new,minimum width=28mm] (reboot) {再起動\\[-1pt]{\scriptsize 受け入れテスト 4・5}};
  \draw[flow] (old) -- node[lbl,above=1mm,font=\scriptsize\ttfamily] {just backup} (file);
  \draw[flow] (file) -- node[lbl,above=1mm,font=\scriptsize\ttfamily] {just restore} (new);
  \draw[flow] (new) -- (reboot);
  \node[ext,below=of file,align=left,font=\scriptsize\gtfamily] (moved)
    {移す: ホストの鍵、RDP の証明書、\\ログイン、設定、\texttt{\string~/work}};
\end{tikzpicture}
\caption{移行の流れ}
\end{figure}

\begin{enumerate}
  \item Orca とエージェントの作業を止める
  \item 書き出す(ホストには保存されない。sudo のパスワードを 1 回聞かれる)
\begin{local}
just backup <ホスト>    # build/backups/<ホスト>-<日時>.tar.zst に書き出す
\end{local}
  \item Docker のボリュームに残したいデータがあれば、手で書き出す
  \item 同じ env.yaml で \code{just iso} を作り、新しいホストを入れる
  \item 構成が終わったら取り込み、再起動する
\begin{local}
just restore <ホスト> build/backups/<ホスト>-<日時>.tar.zst
just ssh <ホスト>       # sudo systemctl reboot
\end{local}
  \item 受け入れテストの 4・5 を行う
\end{enumerate}

\begin{caution}
書き出したファイルにはログインの情報が入る。暗号化された場所に置き、取り込んだら消す。
\end{caution}

\section{just を使わない場合}
%======================================================================
just のレシピがしていることを手で行うときのコマンド。リポジトリの直下で実行する。

\subsection{ISO を作る}
Linux(\code{xorriso} と \code{python3-yaml} が要る):
\begin{local}
curl -fLO https://releases.ubuntu.com/26.04/ubuntu-26.04.1-desktop-amd64.iso
curl -fsSL https://releases.ubuntu.com/26.04/SHA256SUMS | sha256sum -c --ignore-missing
scripts/build-usb.sh ubuntu-26.04.1-desktop-amd64.iso \
    build/agent-host.iso autoinstall/env.yaml
\end{local}
Windows では、Git Bash から Docker の Ubuntu の中で同じことをする。
\begin{local}
MSYS_NO_PATHCONV=1 docker run --rm -v "$(pwd -W):/repo" -w /repo \
  ubuntu:26.04 bash -c 'apt-get update -qq &&
  apt-get install -y -qq xorriso python3-yaml &&
  bash scripts/build-usb.sh build/ubuntu-26.04.1-desktop-amd64.iso \
    build/agent-host.iso autoinstall/env.yaml'
\end{local}

\subsection{状態と記録を見る}
\begin{local}
ssh sysadmin@<ホスト>
\end{local}
\begin{host}
test -f /var/lib/agent-host/provisioned && echo 構成済み
ss -tln | grep 3389
sudo journalctl -u agent-host-provision.service
sudo cat /home/agent/.local/state/agent-host/first-login.log
\end{host}

\subsection{設定やスクリプトを変えたとき}
\code{scripts/stage.sh autoinstall/env.yaml <作業ディレクトリ>} で \code{<作業ディレクトリ>/agent-host/} を作り、
ホストの \code{/opt/agent-host} と入れ替えてから(\code{env.sh} と \code{agent_authorized_keys} は 600、所有者は root)、
\code{sudo /opt/agent-host/provision.sh} を実行する。

\subsection{移行の書き出しと取り込み}
\code{sysadmin} の sudo はパスワードが要り、標準入力は書き出しの受け渡しに使うので、
パスワードは標準入力の先頭の 1 行で渡す。
\begin{local}
read -rsp "sysadmin のパスワード: " PW; echo
printf '%s\n' "$PW" | ssh sysadmin@<ホスト> \
    'sudo -S -p "" agent-host-backup' > agent-host-<ホスト名>-<日付>.tar.zst
{ printf '%s\n' "$PW"; cat agent-host-<ホスト名>-<日付>.tar.zst; } |
    ssh sysadmin@<ホスト> 'sudo -S -p "" agent-host-restore'
unset PW
\end{local}

\subsection{RDP の接続ファイル}
\code{docs/agent-host.rdp.example} をコピーし、\code{full address} をホスト名に直す(改行は CRLF のまま)。

\subsection{手順書の PDF}
リリースした版の PDF は、GitHub の Releases に付いている。手元で作るときは次のとおり(Docker が要る)。
\begin{local}
scripts/local/build-guide.sh     # build/setup-guide/setup-guide.pdf
\end{local}
